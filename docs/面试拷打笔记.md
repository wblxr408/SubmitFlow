# SubmitFlow 面试拷打笔记

面向 CS/AI 校招生招聘场景的实习/校招信息聚合与投递追踪平台面试题库。

---

## 一、项目概述类

### Q1: 介绍一下你这个项目是做什么的？

**参考回答：**

SubmitFlow 是一个面向 CS/AI 在校学生的实习与校招信息聚合与投递追踪平台。主要解决以下几个问题：

1. **信息分散** - 实习/校招信息分散在牛客、应届生、脉脉等多个平台，用户需要频繁切换
2. **投递混乱** - 海投后难以追踪状态，不知道在哪个环节
3. **内推进展不透明** - 不知道内推是否被接收、简历是否被查看
4. **个性化推荐缺失** - 难以找到最适合自己的岗位

核心功能：
- 聚合多平台实习/校招信息（牛客、内推鸭等）
- 支持内推管理、投递追踪、截止提醒
- 基于六维权重的智能推荐算法
- 用户画像（技能向量采集与匹配）
- 多用户认证体系（JWT）

### Q2: 这个项目最大的亮点是什么？

**参考回答：**

1. **推荐算法 V2** - 六维评分体系（知名度、匹配度、城市、紧迫性、转正率、新鲜度），支持用户自定义权重
2. **全文搜索 + 模糊匹配** - 基于 PostgreSQL 的 tsvector 全文搜索和 pg_trgm 模糊匹配
3. **用户画像系统** - 采集用户技能向量（职位方向+技能标签+行业+城市），支持智能推荐
4. **多用户架构** - JWT 认证、密码重置、邮箱验证

### Q4: 为什么选择 Next.js 而不是纯后端框架？

**参考回答：**

| 考虑因素 | Next.js 优势 |
|---------|--------------|
| SSR/SSG | 首页 SEO 友好，API routes 统一管理 |
| 全栈统一 | 一套代码库，前端后端都支持 TypeScript |
| 部署简单 | Vercel/Docker 一键部署 |
| 生态丰富 | React 生态，组件库丰富 |
| API Routes | REST API 和前端页面同构 |

### Q5: 为什么选择 PostgreSQL 而不是 MySQL/MongoDB？

**参考回答：**

1. **全文搜索** - PostgreSQL 内置 tsvector，支持复杂的全文搜索
2. **pg_trgm** - 原生支持模糊匹配，无需额外搜索引擎
3. **JSONB** - 支持半结构化数据（如用户画像的 metadata）
4. **数组类型** - companies 表的 alias_names、brand_names 用数组存储很方便
5. **事务支持** - 完整的 ACID 事务保证数据一致性
6. **性能优化** - 支持部分索引、表达式索引、CTE 查询

### Q6: 为什么没有使用 Redis？

**参考回答：**

1. **简化部署** - 减少基础设施依赖，一台服务器就能跑
2. **数据量可控** - 当前规模（千级岗位、用户）用内存缓存足够
3. **已预留接口** - `SimpleCache` 抽象了缓存层，后续可以无缝切换到 Redis
4. **pg 性能足够** - PostgreSQL 的查询性能对小规模数据足够快

### Q8: 如何设计索引优化查询性能？

**参考回答：**

```sql
-- 1. 主键索引（B-Tree）
PRIMARY KEY (id)

-- 2. 唯一索引
UNIQUE(profile_id, tag_id)

-- 3. 外键索引（加速 JOIN）
FOREIGN KEY (company_id) REFERENCES companies(id)

-- 4. 条件索引（只索引有效数据）
CREATE INDEX idx_jobs_valid ON jobs(status) WHERE status = 'valid'

-- 5. 复合索引（多字段查询）
CREATE INDEX idx_jobs_city_type ON jobs(city, internship_type)

-- 6. 全文搜索索引
CREATE INDEX idx_jobs_search ON jobs USING GIN(search_vector)

-- 7. 模糊匹配索引
CREATE INDEX idx_jobs_title_trgm ON jobs USING GIN(title gin_trgm_ops)
```

### Q9: 数据库迁移是怎么做的？

**参考回答：**

```
src/db/
├── schema.sql           # 初始表结构
├── seed.sql             # 种子数据
└── migrations/
    ├── 006_add_users.sql
    ├── 007_add_user_profile_link.sql
```

2. seed.sql - 填充初始数据
3. 006-012 - 按顺序执行增量迁移

## 四、认证与安全类

### Q10: JWT 认证是如何实现的？

**参考回答：**

```typescript
// 1. 登录时签发 Token
const JWT_SECRET = process.env.JWT_SECRET || process.env.ENCRYPTION_KEY?.slice(0, 32);
jwt.sign({ userId, email, role }, JWT_SECRET, { expiresIn: '7d' });

// 2. Middleware 验证 Token
const payload = jwtVerify(token, encoder.encode(JWT_SECRET));

// 3. API 获取用户上下文
const authContext = await getAuthContext(); // 从 Cookie/Header 解析
```

安全措施：
- Token 过期时间 7 天
- HttpOnly Cookie 防止 XSS
- Secure Cookie 生产环境启用
- SameSite=Lax 防止 CSRF

### Q11: 敏感数据（API Key）如何存储？

**参考回答：**

1. **不存明文** - AI 服务商的 API Key 加密后存储
2. **AES-256-GCM** - 使用 ENCRYPTION_KEY 加密
3. **按需解密** - 只在调用 AI 服务时解密，用完即弃
4. **传输安全** - HTTPS 全程加密

### Q12: SQL 注入如何防范？

**参考回答：**

1. **参数化查询** - 所有用户输入都用 `$1, $2` 占位符
2. **ORM/DB Layer** - 使用 `pg` 的 query 方法封装
3. **输入校验** - zod schema 验证请求体
4. **白名单过滤** - 枚举类型限制（status, type 等）

```typescript
// ✅ 正确：参数化查询
await query('SELECT * FROM jobs WHERE city = $1', [city]);

// ❌ 错误：字符串拼接
await query(`SELECT * FROM jobs WHERE city = '${city}'`);
```

### Q13: XSS 和 CSRF 如何防范？

**参考回答：**

**XSS 防护：**
- React 默认转义 HTML
- CSP (Content Security Policy)
- HttpOnly Cookie

**CSRF 防护：**
- SameSite Cookie
- CSRF Token（可选，JWT Cookie 模式下非必须）
- CORS 白名单

### Q15: 推荐算法是怎么设计的？

**参考回答（v3 增强版）：**

推荐算法经历了三个版本的迭代：

**v1.4 六维评分体系：**
```typescript
score = (
  fame * fameWeight +           // 公司知名度
  match * matchWeight +         // 方向匹配度
  city * cityWeight +           // 城市偏好
  deadline * deadlineWeight +   // 截止紧迫性
  conversion * conversionWeight + // 转正率
  freshness * freshnessWeight    // 新鲜度
)
```

**v3 增强特性：**

```
┌─────────────────────────────────────────────────────────────────┐
│                    推荐算法 v3 架构                                │
│                                                               │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────┐ │
│  │ 负反馈建模    │  │ 兴趣衰减     │  │ 协同过滤              │ │
│  │ Dismiss 惩罚  │  │ 时间衰减因子  │  │ 用户相似度            │ │
│  └──────────────┘  └──────────────┘  └──────────────────────┘ │
│                                                               │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────┐ │
│  │ 热门加权      │  │ 多样性控制   │  │ 冷启动策略            │ │
│  │ log1p 归一化  │  │ 公司去重     │  │ 新用户兜底           │ │
│  └──────────────┘  └──────────────┘  └──────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

**1. 负反馈建模（Dismiss Penalty）：**
```typescript
// 被用户主动 dismiss 的岗位降权 50%
const dismissPenalty = context.dismissedJobs.some(d => d.jobId === job.id) ? 0.5 : 1;
```

**2. 兴趣衰减模型（Decay）：**
| 兴趣类型 | 衰减率/天 | 半衰期 |
|---------|----------|--------|
| 公司 | 0.8% | 90 天 |
| 城市 | 0.5% | 180 天 |
| 技能 | 1.2% | 60 天 |
| 行业 | 0.6% | 120 天 |

**3. 协同过滤（Collaborative Filtering）：**
```typescript
// 用户相似度计算（余弦相似度）
const similarity = cosineSimilarity(userAVector, userBVector);
collaborativeScore = similarity * commonJobCount * 10;
```

**4. 多样性控制（Diversity Control）：**
```typescript
const diversityPresets = {
  保守型: { explorationRatio: 0.10, popularityRatio: 0.40, maxSameCompany: 2 },
  平衡型: { explorationRatio: 0.20, popularityRatio: 0.30, maxSameCompany: 3 },
  探索型: { explorationRatio: 0.35, popularityRatio: 0.20, maxSameCompany: 5 },
};
```

**v3 综合评分公式：**
```typescript
score = sum(dimScore * weight) / sum(weights) * dismissPenalty * (1 + interactionBonus)
```

**城市评分精细化（v3）：**
| 匹配类型 | 分值 |
|---------|------|
| 精确匹配 | 100 |
| 一线城市互通（北京/上海/深圳/广州互认） | 85 |
| 新一线城市互通（杭州/成都/南京等） | 80 |
| 同区域（华东/华南/华北/华中/西南/西北/东北） | 70 |
| 可远程 | 75 |
| 非目标城市 | 30 |

**推荐策略模板（Presets）：**
| 策略 | 适用场景 | 特点 |
|------|---------|------|
| 稳重型 | 已有明确目标 | 高匹配权重，低探索 |
| 海投型 | 快速覆盖 | 高多样性，高热门 |
| 精准型 | 方向明确 | 高匹配，高城市权重 |
| 新人型 | 冷启动 | 热门 + 新发布兜底 |
| 探索型 | 拓宽视野 | 高探索比例 |

**冷启动策略：**
1. 热门岗位（按投递数排序，取 Top 20%）
2. 城市匹配热门（目标城市内按投递数排序）
3. 最新发布（7 天内，按 freshness 排序）

**④ 得分累加与衰减公式：**

每次行为更新时，累加到现有得分上，同时应用时间衰减：

```typescript
async function upsertSkillPreference(
  profileId: number,
  targetType: 'skill' | 'position' | 'industry' | 'city' | 'company',
  targetId: number,
  scoreDelta: number
) {
  // 读取当前记录
  const existing = await query(`
    SELECT id, pos_score, neg_score, last_event_at, event_count
    FROM profile_preferences
    WHERE profile_id = $1 AND target_type = $2 AND target_id = $3
  `, [profileId, targetType, targetId]);

  if (!existing[0]) {
    // 新增
    await execute(`
      INSERT INTO profile_preferences
        (profile_id, target_type, target_id, target_text,
         pos_score, neg_score, event_count, last_event_at, evidence_event_ids)
      VALUES ($1, $2, $3, $4, GREATEST(0, $5), 0, 1, NOW(), ARRAY[$6])
    `, [profileId, targetType, targetId, targetId, scoreDelta, eventId]);
    return;
  }

  const current = existing[0];

  // 应用衰减：旧得分按时间折损后再加新分
  const daysSinceLastEvent = daysBetween(current.last_event_at, new Date());
  const decayRate = DECAY_RATES[targetType]; // skill:0.012/天
  const decayedPosScore = current.pos_score * Math.pow(1 - decayRate, daysSinceLastEvent);

  const newPosScore = Math.min(1.0, decayedPosScore + scoreDelta);

  await execute(`
    UPDATE profile_preferences
    SET
      pos_score = $1,
      event_count = event_count + 1,
      last_event_at = NOW(),
      evidence_event_ids = array_append(evidence_event_ids, $2)
    WHERE id = $3
  `, [newPosScore, eventId, current.id]);
}
```

| 维度 | 衰减率/天 | 半衰期 | 理由 |
|------|----------|--------|------|
| skill | 1.2% | 60 天 | 技术栈变化较快，需及时更新 |
| position | 0.8% | 90 天 | 方向相对稳定 |
| industry | 0.6% | 120 天 | 行业偏好变化慢 |
| city | 0.4% | 180 天 | 城市选择非常稳定 |
| company | 0.8% | 90 天 | 目标公司可能有变化 |

**⑤ 置信度计算：**

```typescript
// 置信度 = 事件次数的 log 增速 × 时间新鲜度
function calcConfidence(eventCount: number, lastEventAt: Date): number {
  const daysSince = daysBetween(lastEventAt, new Date());
  const freshness = Math.exp(-daysSince / 30); // 30 天内新鲜
  const countBonus = Math.min(1.0, Math.log(1 + eventCount) / Math.log(11));
  return countBonus * 0.6 + freshness * 0.4;
}
```

**扩展策略①：树结构扩展（规则，最快）：**

```typescript
// 基于技能树的父子/兄弟关系做扩展
function expandFromTree(nodeId: number): number[] {
  const node = getNode(nodeId);
  const candidates: number[] = [];

  // P1: 兄弟节点（同父节点，权重最高）
  const siblings = getNodesByParent(node.parent_id);
  candidates.push(...siblings.filter(n => n.id !== nodeId).map(n => n.id));

  // P2: 父节点路径（同链路上级）
  let parentId = node.parent_id;
  while (parentId) {
    candidates.push(parentId);
    const parent = getNode(parentId);
    parentId = parent?.parent_id ?? null;
  }

  // P3: 叔伯节点（父节点的兄弟）
  const parent = getNode(node.parent_id);
  if (parent?.parent_id) {
    const uncles = getNodesByParent(parent.parent_id);
    candidates.push(...uncles.filter(n => n.id !== node.parent_id).map(n => n.id));
  }

  // 过滤已选节点，按层级排序（兄弟优先）
  return dedupAndSort(candidates, selectedIds);
}
```

**扩展策略②：岗位共现扩展（数据驱动，最准）：**

岗位库中同时出现的技能对，代表了真实的技术栈组合：

```sql
-- 预计算技能共现表（每日定时刷新，基于真实岗位数据）
CREATE TABLE skill_cooccurrence AS
SELECT
  a.tag_id AS skill_a,
  b.tag_id AS skill_b,
  COUNT(*) AS co_count,
  COUNT(*) * 1.0 / (
    SELECT COUNT(DISTINCT job_id) FROM job_tags WHERE tag_id = a.tag_id
  ) AS normalized_score  -- 归一化：消除高频技能偏差
FROM job_tags a
JOIN job_tags b ON a.job_id = b.job_id AND a.tag_id < b.tag_id
WHERE a.job_id IN (SELECT id FROM jobs WHERE status = 'valid')
GROUP BY a.tag_id, b.tag_id
HAVING COUNT(*) >= 3;  -- 共现至少 3 个岗位才有效

CREATE INDEX ON skill_cooccurrence(skill_a, normalized_score DESC);

-- 扩展查询：给定已选技能集合，推荐共现技能
WITH seed_tags AS (
  SELECT unnest($1::int[]) AS tag_id
),
co_scores AS (
  SELECT
    sc.skill_b AS tag_id,
    SUM(sc.normalized_score) AS cooc_score,
    COUNT(*) AS cooc_count
  FROM skill_cooccurrence sc
  JOIN seed_tags st ON sc.skill_a = st.tag_id
  WHERE sc.skill_b != ALL($1::int[])  -- 排除已选
  GROUP BY sc.skill_b
  HAVING COUNT(*) >= 1  -- 至少被 1 个种子技能共现
)
SELECT
  tag_id,
  cooc_score,
  cooc_count,
  cooc_score * LOG(1 + cooc_count) AS final_score  -- 共现次数 log 加权
FROM co_scores
ORDER BY final_score DESC
LIMIT $2;
```

**扩展策略③：向量化 KNN 扩展（语义，最深）：**

每个技能标签预计算一个语义向量（OpenAI embedding），用于发现无共现记录但语义相近的技能：

```typescript
// 技能标签向量化（预计算，存入 skill_embeddings 表）
interface SkillEmbedding {
  tag_id: number;
  embedding: number[]; // 1536-dim OpenAI text-embedding-3-small
}

// 扩展实现：从种子找 K 个最近邻
async function knnExpand(
  seedTagIds: number[],
  k: number = 5
): Promise<Array<{ tagId: number; similarity: number }>> {
  // 1. 获取种子的向量
  const seedVectors = await query(`
    SELECT tag_id, embedding FROM skill_embeddings
    WHERE tag_id = ANY($1)
  `, [seedTagIds]);

  if (seedVectors.length === 0) return [];

  // 2. 计算 centroid（多标签的均值向量）
  const centroid = meanVector(seedVectors.map(v => v.embedding));

  // 3. 找 K 个最近邻
  const candidates = await query(`
    SELECT tag_id, embedding
    FROM skill_embeddings
    WHERE tag_id != ALL($1)
  `, [seedTagIds]);

  const scored = candidates
    .map(row => ({
      tagId: row.tag_id,
      similarity: cosineSimilarity(centroid, row.embedding),
    }))
    .filter(s => s.similarity > 0.6)  // 过滤噪音
    .sort((a, b) => b.similarity - a.similarity);

  return scored.slice(0, k);
}

// 余弦相似度
function cosineSimilarity(a: number[], b: number[]): number {
  let dot = 0, normA = 0, normB = 0;
  for (let i = 0; i < a.length; i++) {
    dot += a[i] * b[i];
    normA += a[i] * a[i];
    normB += b[i] * b[i];
  }
  return dot / (Math.sqrt(normA) * Math.sqrt(normB));
}
```

**四路综合评分与推荐排序：**

```typescript
interface ExpansionCandidate {
  tagId: number;
  source: 'tree' | 'cooc' | 'knn' | 'cf';
  treeScore: number;    // 0 或 1（有/无）
  coocScore: number;   // 归一化共现分
  knnScore: number;    // 0~1 相似度
  cfScore: number;     // 归一化 CF 分
}

function rankCandidates(candidates: ExpansionCandidate[]): ExpansionCandidate[] {
  return candidates
    .map(c => ({
      ...c,
      finalScore:
        c.treeScore * 0.20 +   // 树扩展：规则可靠，权重适中
        normalize(c.coocScore) * 0.40 +  // 共现：数据驱动，最准确
        c.knnScore * 0.25 +    // KNN：语义理解，补充冷门
        normalize(c.cfScore) * 0.15   // CF：用户行为验证
    }))
    .sort((a, b) => b.finalScore - a.finalScore);
}

// min-max 归一化
function normalize(value: number): number {
  // 共现和 CF 的原始分差异较大，需要归一化到 [0, 1]
  // 由 max_score 在查询时作为除数传入
  return value; // 在 SQL 层已完成归一化
}
```

**画像在推荐中的应用（多维度 match_score 计算）**

用户画像最终服务于推荐引擎。不同于简单的 tag 匹配，v1.7 采用**维度级加权匹配**，每个维度独立贡献分数：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    多维度 match_score 计算流程                                │
│                                                                             │
│  岗位要求的每个 tag 都标注了维度：                                          │
│    [NLP: ml_domain=0.9, language=0.1]                                    │
│    [Python: language=1.0]                                                 │
│    [FastAPI: framework=0.8, language=0.2]                                 │
│    [分布式: system_knowledge=1.0]                                         │
│    [字节: company_tier=1.0]                                               │
│    [北京: city=1.0]                                                       │
│                                                                             │
│  每个维度独立计算：                                                         │
│    dimensionScore = Σ(tagScore × dimWeight) / Σ(dimWeight)               │
│                                                                             │
│  维度权重（可用户配置）：                                               │
│    os_knowledge(0.06) + networking(0.06) + db_theory(0.06) +         │
│    distributed_systems(0.08) + hpc(0.04) + pl_theory(0.03) +        │
│    architecture(0.04) + dsa(0.07) +                                  │
│    ml_domain(0.10) + language(0.12) + framework(0.08) +            │
│    city(0.08) + company_tier(0.07) + position_type(0.12)            │
│                                                                             │
│  缺失维度惩罚：                                                            │
│    岗位要求 ml_domain，用户无 ml_domain 记录 → 该维度得分 = 0             │
│    penalty = Σ(missing_dim_score × dim_weight) × 0.3                     │
│                                                                             │
│  最终 match_score = weightedSum - penalty ∈ [0, 100]                      │
└─────────────────────────────────────────────────────────────────────────────┘
```

**完整计算代码：**

```typescript
// 维度权重配置（可用户自定义）
const DIM_WEIGHTS: Record<Dimension, number> = {
  // 第一层：职位方向
  position_type:      0.12,

  // 第二层：技术栈
  language:           0.12,   // 编程语言是硬技能
  framework:          0.08,
  infra:              0.05,

  // 第三层：知识领域
  os_knowledge:       0.06,   // 操作系统
  networking:         0.06,   // 计算机网络
  db_theory:          0.06,   // 数据库原理
  distributed_systems: 0.08,  // 分布式系统（核心）
  hpc:                0.04,   // 并行计算
  pl_theory:          0.03,   // 编译器原理
  architecture:       0.04,   // 体系结构
  dsa:               0.07,   // 数据结构与算法（面试核心）

  // 第四层：AI/ML
  ml_domain:          0.10,   // AI 学生：ML 方向关键

  // 第五层：安全
  security_knowledge: 0.03,

  // 第六层：图形学
  graphics:           0.03,

  // 第七层：学术背景
  research_area:      0.08,
  publication:        0.05,
  pub_count:         0.02,

  // 第八层：偏好约束
  industry_preference: 0.04,
  city_preference:   0.08,
  company_tier:      0.07,
  job_type:          0.05,
};

type Dimension =
  | 'position_type' | 'language' | 'framework' | 'infra'
  | 'os_knowledge' | 'networking' | 'db_theory' | 'distributed_systems'
  | 'hpc' | 'pl_theory' | 'architecture' | 'dsa'
  | 'ml_domain' | 'security_knowledge' | 'graphics'
  | 'research_area' | 'publication' | 'pub_count'
  | 'industry_preference' | 'city_preference' | 'company_tier' | 'job_type';

interface TagDimensionMapping {
  tag_id: number;
  dimension: Dimension;
  dim_weight: number;  // 该 tag 在该维度内的权重（总和可 > 1）
}

// Step 1: 每个 tag 到维度的映射（在 job_tags 中预存）
// job_tags 表增加 mapping 字段（JSONB）：
// { dimension: 'ml_domain', weight: 0.8, tag_id: 7 }

async function calcMatchScoreV3(
  jobId: number,
  profileId: number
): Promise<number> {
  // Step 1: 获取岗位的 tag 及其维度映射
  const jobTags = await query(`
    SELECT
      t.id AS tag_id,
      t.label,
      jt.dim_mappings AS mappings
    FROM job_tags jt
    JOIN tags t ON t.id = jt.tag_id
    WHERE jt.job_id = $1
  `, [jobId]);

  if (jobTags.length === 0) return 50;

  // Step 2: 收集所有 tag_id，批量查询用户画像
  const allTagIds = jobTags.flatMap(t => {
    const mappings: TagDimensionMapping[] = t.mappings ?? [];
    return mappings.map(m => m.tag_id);
  });

  const userPrefs = await query(`
    SELECT target_id, target_type, pos_score, neg_score, confidence
    FROM profile_preferences
    WHERE profile_id = $1 AND target_id = ANY($2)
  `, [profileId, allTagIds]);
  const prefMap = new Map(userPrefs.map(p => [`${p.target_type}:${p.target_id}`, p]));

  // Step 3: 按维度聚合得分
  const dimScores: Partial<Record<Dimension, { weighted: number; total: number }>> = {};
  const dimMissing: Set<Dimension> = new Set(Object.keys(DIM_WEIGHTS) as Dimension[]);

  for (const jt of jobTags) {
    const mappings: TagDimensionMapping[] = jt.mappings ?? [];

    for (const mapping of mappings) {
      const key = `${mapping.dimension}:${mapping.tag_id}`;
      const pref = prefMap.get(key);
      const dimWeight = mapping.dim_weight;

      if (pref) {
        dimMissing.delete(mapping.dimension);
        const netScore = pref.pos_score + pref.neg_score;
        const effective = Math.max(0, netScore) * (pref.confidence ?? 0.5);
        const w = dimWeight * effective;

        if (!dimScores[mapping.dimension]) {
          dimScores[mapping.dimension] = { weighted: 0, total: 0 };
        }
        dimScores[mapping.dimension]!.weighted += w;
        dimScores[mapping.dimension]!.total += dimWeight;
      }
    }
  }

  // Step 4: 计算各维度分数
  let totalScore = 0;
  let totalWeight = 0;
  let penalty = 0;

  for (const [dim, cfg] of Object.entries(DIM_WEIGHTS)) {
    const d = dim as Dimension;
    const dimData = dimScores[d];

    if (dimData && dimData.total > 0) {
      const dimScore = dimData.weighted / dimData.total;
      totalScore += dimScore * cfg;
      totalWeight += cfg;
    } else if (dimMissing.has(d)) {
      // 缺失维度：记录惩罚
      penalty += cfg * 0.3;
    }
  }

  if (totalWeight === 0) return 50;

  const rawScore = totalScore / totalWeight;
  const finalScore = Math.max(0, rawScore - penalty) * 100;
  return Math.round(finalScore); // ∈ [0, 100]
}
```

**维度缺失惩罚机制：**

```
例：用户未填写 research_area（研究方向），但投递了研究型岗位
→ research_area 维度得分 = 0
→ penalty = research_area_weight × 0.3 = 0.08 × 0.3 = 0.024
→ 对总分影响约 2.4 分（温和惩罚，引导用户补充信息）
```

**推荐时的 match_score 用法：**

```typescript
// 六维评分的 match 维度使用多维度 match_score
const matchScore = await calcMatchScoreV3(job.id, profileId);
const finalScore =
  fame * fameWeight +
  matchScore * matchWeight +     // 多维度 match（0-100）
  cityScore * cityWeight +
  deadlineScore * deadlineWeight +
  conversionScore * conversionWeight +
  freshnessScore * freshnessWeight;
```

**数据存储：profile_preferences 表设计（15 维度）**

```sql
-- 维度枚举（20 维度）
-- position_type / language / framework / infra /
-- os_knowledge / networking / db_theory / distributed_systems /
-- hpc / pl_theory / architecture / dsa /
-- ml_domain / security_knowledge / graphics /
-- research_area / publication / pub_count /
-- industry_preference / city_preference / company_tier / job_type

CREATE TABLE profile_preferences (
  id BIGSERIAL PRIMARY KEY,
  profile_id BIGINT NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,

  -- 维度 + 目标值（key）
  target_type VARCHAR(30) NOT NULL,
  target_id BIGINT,                              -- 可 JOIN 到 tags.id（可为空）
  target_text VARCHAR(200) NOT NULL,             -- 关键词冗余，用于展示

  -- 得分（核心字段）
  pos_score NUMERIC(5,3) NOT NULL DEFAULT 0 CHECK (pos_score BETWEEN 0 AND 1),
  neg_score NUMERIC(5,3) NOT NULL DEFAULT 0 CHECK (neg_score BETWEEN -1 AND 0),
  net_score NUMERIC(5,3) GENERATED ALWAYS AS (pos_score + neg_score) STORED,

  -- 行为统计
  event_count INT NOT NULL DEFAULT 1,
  first_event_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  last_event_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  -- 置信度
  confidence NUMERIC(3,2) GENERATED ALWAYS AS (
    LEAST(1.0,
      (LOG(1 + event_count) / LOG(11)) * 0.6 +
      (1 - (EXTRACT(EPOCH FROM (NOW() - last_event_at)) / (30 * 86400))) * 0.4
    )
  ) STORED,

  -- 证据链
  evidence_event_ids TEXT[] DEFAULT '{}',

  -- 约束
  UNIQUE(profile_id, target_type, target_id)
);

-- 各维度独立索引（加速按维度查询）
CREATE INDEX ON profile_preferences(profile_id, target_type, net_score DESC)
  WHERE target_type IN ('language', 'framework', 'ml_domain', 'research_area');

CREATE INDEX ON profile_preferences(profile_id, target_type, net_score DESC)
  WHERE target_type IN ('city_preference', 'company_tier', 'job_type');
```

**搜索与过滤逻辑：**

```typescript
// 完整的过滤管道
function filterAndSortTags(
  allTags: Tag[],
  selectedIds: Set<number>,
  filters: FilterState,
): Tag[] {
  let result = allTags;

  // Step 1: 关键词搜索（tag.label 或 tag.slug 模糊匹配）
  if (filters.query.trim()) {
    const q = filters.query.toLowerCase();
    result = result.filter(t =>
      t.label.toLowerCase().includes(q) ||
      t.slug.toLowerCase().includes(q)
    );
  }

  // Step 2: 分类过滤
  if (filters.activeGroupName) {
    result = result.filter(t => t.group_name === filters.activeGroupName);
  }

  // Step 3: 等级过滤
  if (filters.activeSkillLevel) {
    result = result.filter(t => t.skill_level === filters.activeSkillLevel);
  }

  // Step 4: 元标签过滤
  if (filters.activeMetaTag) {
    result = result.filter(t => t.meta_tags?.includes(filters.activeMetaTag));
  }

  // Step 5: 排序
  const SORT_FN = {
    label: (a: Tag, b: Tag) => a.label.localeCompare(b.label),
    popularity: (a: Tag, b: Tag) => b.popularity - a.popularity,
    skill_level: (a: Tag, b: Tag) =>
      LEVEL_ORDER.indexOf(a.skill_level) - LEVEL_ORDER.indexOf(b.skill_level),
  }[filters.sortBy];

  result = [...result].sort((a, b) => {
    const cmp = SORT_FN(a, b);
    return filters.sortDir === 'asc' ? cmp : -cmp;
  });

  return result;
}

// Group by group_name for grid view
function groupByCategory(tags: Tag[]): Map<string, Tag[]> {
  const groups = new Map<string, Tag[]>();
  for (const tag of tags) {
    const key = tag.group_name ?? '其他';
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key)!.push(tag);
  }
  // 按组内热度排序，保持组的相对顺序
  for (const [, groupTags] of groups) {
    groupTags.sort((a, b) => b.popularity - a.popularity);
  }
  return groups;
}
```

```typescript
export async function GET(request: NextRequest) {
  const { searchParams } = new URL(request.url);
  const query = searchParams.get('query');
  const groupName = searchParams.get('group_name');
  const skillLevel = searchParams.get('skill_level');
  const sort = searchParams.get('sort') ?? 'label';
  const limit = parseInt(searchParams.get('limit') ?? '100');

  let sql = `
    SELECT id, slug, label, group_name, color_hex,
           skill_level, learning_cost, popularity, meta_tags
    FROM tags
    WHERE 1=1
  `;
  const params: unknown[] = [];
  let idx = 1;

  if (query) {
    sql += ` AND (label ILIKE $${idx} OR slug ILIKE $${idx})`;
    params.push(`%${query}%`);
    idx++;
  }

  if (groupName) {
    sql += ` AND group_name = $${idx}`;
    params.push(groupName);
    idx++;
  }

  if (skillLevel) {
    sql += ` AND skill_level = $${idx}`;
    params.push(skillLevel);
    idx++;
  }

  // 排序
  const sortCol = { label: 'label', popularity: 'popularity DESC', skill_level: "CASE skill_level WHEN '入门' THEN 1 WHEN '初级' THEN 2 WHEN '中级' THEN 3 WHEN '高级' THEN 4 END" }[sort] ?? 'label';
  sql += ` ORDER BY ${sortCol} LIMIT $${idx}`;
  params.push(limit);

  const rows = await query(sql, params);
  return NextResponse.json({ tags: rows });
}

export async function GET() {

export async function GET(
  request: NextRequest,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const { searchParams } = new URL(request.url);
  const k = parseInt(searchParams.get('k') ?? '5');

  // 方式 A: 用 embedding 做 KNN（如果有向量）
  // 方式 B: 用岗位共现表找相似标签
  const rows = await query(`
    WITH seed_tag AS (
      SELECT embedding FROM tag_embeddings WHERE tag_id = $1
    ),
    similar AS (
      SELECT te.tag_id, te.embedding, seed_tag.embedding AS seed_emb
      FROM tag_embeddings te, seed_tag
      WHERE te.tag_id != $1
    )
    SELECT similar.tag_id, t.label,
           (similar.embedding <=> similar.seed_emb) AS distance
    FROM similar
    JOIN tags t ON t.id = similar.tag_id
    ORDER BY distance
    LIMIT $2
  `, [parseInt(id), k]);

  return NextResponse.json({
    similar: rows.map(r => ({ id: r.tag_id, label: r.label, distance: r.distance }))
  });
}
```

```typescript
// 1. 在 HTML 中定位 marker
const marker = 'window.__INITIAL_STATE__=';
const markerIndex = html.indexOf(marker);

// 2. 找到 JSON 起始位置（跳过赋值语句的 =）
while (index < html.length && html[index] !== '{') { index++; }

// 3. 平衡括号解析完整 JSON（处理嵌套和字符串中的括号）
function sliceBalancedJson(content: string, startIndex: number): string {
  let depth = 0, inString = false, escaped = false;
  for (let i = startIndex; i < content.length; i++) {
    const char = content[i];
    if (escaped) { escaped = false; continue; }
    if (char === '\\' && inString) { escaped = true; continue; }
    if (char === '"') { inString = !inString; continue; }
    if (inString) continue;
    if (char === '{') depth++;
    if (char === '}') { depth--; if (depth === 0) return content.slice(startIndex, i + 1); }
  }
  throw new Error('JSON is incomplete');
}

// 4. 深度优先搜索收集所有岗位卡片（WeakSet 防循环引用）
function collectJobCards(value: unknown): NiukeJobCard[] {
  const seen = new WeakSet<object>();
  const jobs = new Map<number, NiukeJobCard>();
  const visit = (current) => {
    if (!current || typeof current !== 'object') return;
    if (seen.has(current)) return;
    seen.add(current);
    if (Array.isArray(current)) { current.forEach(visit); return; }
    const job = normalizeJobCard(current as Record<string, unknown>);
    if (job) jobs.set(job.id, job);
    Object.values(current).forEach(visit);
  };
  visit(value);
  return [...jobs.values()];
}
```

### Q39: 如何防止爬虫被反爬？

**参考回答：**

```typescript
const payload = await verifyAuthToken(token);
if (!payload) {
  return NextResponse.json({ error: 'TOKEN_EXPIRED' }, { status: 401 });
}

// 2. 路径匹配（静态，无 IO）
if (isPublicPath(pathname)) return NextResponse.next();

headers.set('x-user-id', String(payload.userId));

headers.set('x-user-role', payload.role);
```

### Q43: 中间件的 PUBLIC_PATHS 白名单是如何设计的？

**参考回答：**

```typescript
const PUBLIC_PATHS = [
  // 页面路由（无需登录即可访问）
  '/login',
  '/register',
  '/forgot-password',
  '/verify-email',

  // API 认证相关（无需 JWT）
  '/api/auth/register',
  '/api/auth/login',
  '/api/auth/forgot-password',
  '/api/auth/reset-password',
  '/api/auth/verify',

  // 公开数据 API
  '/api/health',               // 健康检查（监控用）
  '/api/graph/taxonomy',       // 技能树分类（公开数据）
  '/api/graph/preferences',    // 技能偏好（登录后才有数据，但读取无需认证）
];

// 匹配逻辑：精确匹配 OR 前缀匹配
function isPublicPath(pathname: string): boolean {
  return PUBLIC_PATHS.some(
    (publicPath) =>
      pathname === publicPath || pathname.startsWith(publicPath + '/'),
  );
}
```

**设计原则：**
1. **最小权限** — 默认拒绝，有需要才加入白名单
2. **前缀支持** — `/api/auth/` 下所有子路径自动放行
3. **职责分离** — 中间件只做认证，API Route 内部再做业务权限校验
4. **分类清晰** — 页面路由和 API 路由分开维护
